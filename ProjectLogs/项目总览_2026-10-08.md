# PICTOUR 项目总览与开发基线

PICTOUR 是 Godot 4.7.2 制作的 2.5D 平台解谜原型，以图层轮换、物件跨层和无人机视角组合空间规则。本项目参加 TapTap 2026 聚光灯 21 天游戏创作挑战，当前重点是让核心机制稳定、形成可通关与可恢复的玩法流程。

本基线对应代码 `948b7e4`，记录于 2026-10-08，保留初次审查时的状态。随后新增的两层序章功能白模、核心修复和验证见 [序章白模实现记录](序章白模实现_2026-10-08.md)，当前运行入口以 README 为准。`dev` 是用户的大地图与美术实验路线，从 main 起步；队友另一路探索关卡式设计，目前尚未上传 GitHub。协作流程见 [协作与 Git 规范](协作与Git规范.md)，agent 执行规则见 [AGENTS](../AGENTS.md)。

## 玩法意图与当前实现

玩家改变单个物件所在层时，物件画面尺寸和中心应保持连续，实际碰撞尺寸与真实位置改变。整体轮换图层时，物件真实状态不变，画面大小、视差和玩家碰撞内容层改变。无人机把锚点从人物移开，让人物身体也成为可换层物件。

策划案包含森林的尺寸谜题、城市的纵向视角谜题和工厂的光影裁切谜题。这些是设计方向，仓库目前只有一个白模原型关卡，并未实现三套完整关卡。

| 内容 | 当前状态 |
|---|---|
| 人物水平移动、接地跳跃 | 已有实现 |
| 整体图层轮换、单物件换层、视觉代理 | 已有实现，需边界回归 |
| 鼠标选中与方块交互 | 已有实现，重叠物件选取顺序需修正 |
| 无人机 | 接地召唤，默认活动距离 400；移动与返回身体已有实现 |
| 关卡参数 | 层数、倍率、当前槽位可编辑；任意配置尚未完整验证 |
| 影子 | 几何与显示原型；生命周期、启停与跨层稳定性未完成 |
| 工厂布尔裁切与静止计时 | 未实现 |
| Goal 通关、关卡加载、重开 | 未形成完整流程 |
| 正式美术、音效、UI、存档 | 无对应完整系统或正式资产 |
| 平台导出与投稿包 | 无导出预设，未验证 |

## 目录与数据流

代码基线 `948b7e4` 跟踪 40 个文件：11 个 `.gd`、11 个 `.gd.uid`、9 个 `.tscn`、5 个 Markdown 和 4 个配置文件，不含本轮新增规范。源文件均为文本，尚无外部美术、音频、插件、测试框架或 CI。

| 位置 | 职责 |
|---|---|
| `project.godot` | 入口、自动加载、输入、1280×720、Mobile 与 D3D12 |
| `Prototype_Game.tscn` | 总装 Level、Player、Camera、System |
| `Level/Level.gd` | 层数、倍率、当前层参数，写入 Global |
| `Level/Prototype_Level.tscn` | 默认四内容层白模，含方块、地面、Goal 和投影物件 |
| `System/Global.gd` | 参数、全局选中对象、输入与事件 |
| `System/System_Controller.gd` | 自动收集 DepthLayer、相机、轮换、换层、无人机协调 |
| `Component/Layer/` | 内容层模板 `Depth_Layer.tscn` 与子物件刷新 |
| `Component/Object/Layer_Object.gd` | 共用视觉、碰撞、跨层换算 |
| `Component/Object/` 各类型 | Box、Ground、Goal、Player_Object、Shadowed_Geometry |
| `Component/Player/` | 人物与无人机的可操作控制体 |

启动时 System 调用 Level 的 `write_to_global()`，扫描关卡直接子节点建立内容层数组。每帧相机跟随控制体，系统以相机世界位置为锚点刷新所有物件的视觉代理。

`layer_id` 固定，`slot` 随整体轮换变化。内容层使用 `layer_id + 1` 作为碰撞位，玩家通过切换碰撞位进入当前活动内容层。单物件换层时重设父节点，按旧槽与新槽倍率之比改变位置和 `CollisionBox.scale`。

默认配置为四层、相邻倍率 `0.8`、当前槽位 `1`，显示倍率为 `1.25 / 1.0 / 0.8 / 0.64`。策划案和 10 月 6 日文档中的 `0.75` 是早期设计参数，尚待团队决定最终手感；本轮没有改动游戏参数。

## 当前需要验证或修复的问题

下列问题来自源码与场景审查；除启动检查外，尚未执行带画面的交互复现。它们作为后续任务候选，不表示本轮已修复。

| 问题 | 证据与影响 |
|---|---|
| 影子依初始槽位分配数组 | `Shadowed_Geometry.gd` 只在 `_ready()` 按初始位置创建；换层后未统一关闭，其他参数或初始状态可能索引越界 |
| 关卡参数写入晚于物件初始化 | `System_Controller._ready()` 才写入参数，影子子节点此前已按默认或上一关 Global 建立数组；非默认关卡不能只依 Inspector 配置可靠初始化 |
| Goal 挂载 Box 脚本 | `Goal.tscn` 引用 `Box.gd`，没有完成判定与反馈 |
| 层遍历筛选过宽 | `Depth_Layer.gd` 用 `child is Object`，普通辅助节点也会被调用物件方法 |
| 鼠标选取比较局部 z | `Global.gd` 比较 Area2D 自身 `z_index`，不能保证与继承的最终绘制顺序一致 |
| 身体释放后仍可能被选中 | `System_Controller.gd` 删除 player_body 未清理 `Global.object_selected` |
| 人物比例未复制至新身体 | 再次召唤无人机仅复制位置，需检查人物经过缩放后的往返一致性 |
| 初始无人机碰撞未禁用 | `Player.tscn` 的无人机碰撞仅隐藏，未设置 `disabled`，需验证初始人物碰撞 |
| 初始化碰撞依 slot | `Layer_Object.gd` 初始化使用 slot，换层使用 layer_id，动态创建时需检查一致性 |
| 配置输入缺少完整约束 | 层数、槽位、倍率和碰撞位的完整有效性尚无统一验证；System 在 level 非空断言前调用该对象 |
| 世界与局部坐标混用风险 | 跨层和无人机距离使用局部位置、相机使用全局锚点；适配前总装根、Level、DepthLayer 须保持零位置、零旋转、单位缩放，整体平移容器也会破坏假设 |

10 月 7 日日志中的固定槽位枚举、`set_slot(<4)` 和 z_index 更新时机已与当前代码不一致：当前 slot 是普通 int，set_slot 已移除，LayerObject 仍每帧更新视觉 z。日志保留历史内容，以本基线和实际源码为当前依据。

## 开发建议

用户已确定下一阶段目标：设计并搭建完整第一章大地图、验证玩法，并探索程序化与 AI 辅助的唯美治愈童话美术实验路径，先做 Windows 原型。我们可以在 dev 修改公共系统来支持该路线，不要求与队友的关卡式设计同步。

建议先定义第一章地图的区域、教学顺序、关键解法和恢复点，再用白模连通地图并试玩。选取对象有效性、无人机往返和重开等问题按地图需要修复；影子和工厂裁切是否进入第一章由设计决定。美术实验用少量可比较的区域样本验证风格、生成成本与引擎表现，再扩大接入。此顺序是技术建议，具体设计与验收范围由用户和 agent 继续确定。

层数参数的通用化范围、`0.8` 与策划 `0.75` 的取舍、光影裁切的最终规则，都需要结合体验目标决定；不为整理规范擅自改变设计。
