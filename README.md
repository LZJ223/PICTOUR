# PICTOUR

一款使用 Godot 4 开发的 2.5D 平台跳跃解谜游戏。玩家通过操纵图层与视角，让物体在“画面大小”“实际大小”和“所在位置”之间产生差异。

当前项目处于核心机制验证与白模关卡开发阶段。

## 核心机制

场景包含四个可循环轮换的景深槽位：

| 槽位 | 显示倍率 |
|---|---:|
| 前景层 | 1.25 |
| 关卡层 | 1.0 |
| 中景层 | 0.8 |
| 后景层 | 0.64 |

- **转换物体图层**：画面大小不变，实际尺寸和真实位置改变。
- **轮换整体图层**：实际状态不变，画面大小、视差和当前碰撞层改变。
- **使用无人机**：将视角锚点从人物转移到无人机，使人物进入视差系统。

> 换物体，改变实际；换图层，改变画面；换锚点，让人物进入透视系统。

## 运行项目

环境要求：Godot `4.7.2-stable`。

1. 使用 Godot 导入 `project.godot`。
2. 打开项目。
3. 按 `F5` 运行主场景 `Prototype_Game.tscn`。

Windows PowerShell：

```powershell
& "C:\Program Files\Godot\Godot_v4.7.2-stable_win64.exe" --editor --path "D:\交大云盘\202610gamejam\PICTOUR"
```

## 操作

| 操作 | 按键 |
|---|---|
| 左右移动 | A / D |
| 跳跃 | Space |
| 无人机上下移动 | W / S |
| 正向/反向图层操作 | Q / E |
| 选择物体 | 鼠标左键 |
| 开启或关闭无人机 | Page Up |

Q/E 的行为取决于是否选中物体：未选中时轮换全部图层，选中后只转换该物体。

## 项目结构

```text
PICTOUR/
├─ Component/          # 图层、玩家和景深物体
├─ Level/              # 关卡场景
├─ Shader/             # 图层滤镜和选择描边
├─ System_Script/      # 全局输入与系统协调
├─ Project_Logs/       # 架构及历史开发文档
├─ Prototype_Game.tscn # 当前主场景
└─ project.godot
```

物体将真实物理状态保存在根节点中，并通过独立的 `VisualRoot` 计算景深缩放和视差，避免画面移动干扰物理世界。

## 通关存档

`SaveSystem` 自动加载并维护 `user://progress.json`。`completed_levels` 为十二个布尔值，依次对应第 1～12 关；`preferences` 保存 `fullscreen`（默认 `false`）、`skip_dialogue`（默认 `false`）、`progress_limit_enabled`（默认 `true`）；`key_bindings` 保存九项操作的物理键码和左右位置。启动时读取已有进度、偏好和键位，文件不存在时创建初始存档。旧的十二布尔数组和未含键位的旧存档会自动迁移，保留已有数据并补齐默认项。

正常玩家触发 Goal 后，立即将该关标记为 `true` 并写盘，随后执行原有通关转场。重复通关保留已有进度。其他系统可通过 `SaveSystem.is_level_completed(level_id)` 查询通关状态，编号范围为 1～12。偏好修改使用 `SaveSystem.set_preference(key, value)`；改键使用 `SaveSystem.set_key_binding(action, event)`；重置使用 `SaveSystem.reset_progress()`，清空十二关记录并保留用户偏好和键位。写入采用临时文件替换，非法数据不会部分覆盖内存状态。

存档回归入口为 `tests/save_system_test.tscn`，应在隔离的用户目录中运行；第二次启动追加 `-- --verify-persisted` 可验证跨进程读取。

## 字母收集

将 `Component/Collection/Collection.tscn` 直接放到关卡的 `DepthLayer` 下，通过检查器的 `Character` 选择 P、I、C、T、O、U、R。物件无实体碰撞箱，不可选取或换层，不留影、不参与影子切割；只有同层正常状态的玩家本体能拾取。待机时浮动并随机倾斜，拾取时先下沉、再上升淡出，动画结束落盘并停用。

存档的 `collected_letters` 为七个独立布尔值，旧存档默认全部未收集。Main 的 `Logo/Logo_字母` 可见性同步存档；`Logo_Back` 和 `Logo_Front` 保持原有结构。重置存档同时清空关卡和字母进度，保留偏好、音量和键位。

场景结构、参数与隔离回归入口见 [字母收集物说明](Component/Collection/README.md)。

## 选关界面

主菜单的选关和设置面板以场景中原本的布局位置为基准，相对于背景向上滑入、向下滑出后隐藏，默认耗时 0.22 秒，可在 Main 根节点的 `submenu_slide_duration` 调整。面板不补偿镜头位移，支持动画中返回、重开和窗口缩放；离场立即取消按键监听和重置蓄力，滑动期间暂停面板的鼠标及焦点交互。

主菜单的 `LevelSelection` 实例化 `Interface/UI/Levels.tscn`，保留场景中十二个按钮的布局和关卡图标。每次打开或存档改变时刷新：已完成关卡使用完成背景；第一关或前一关已完成的关卡使用解锁背景；其他关卡使用锁定背景，屏蔽悬停与点击。取消“进度限制”后所有未完成关卡均解锁，不改动通关记录；重新勾选后恢复按进度锁定。

可用按钮的两张贴图同步播放悬停放大与随机倾斜，按钮命中范围保持原样。`Levels.gd` 默认放大至 `1.06` 倍，倾斜范围为 `±4°`，移出、关闭菜单或窗口失焦后复原。

选关回归入口为 `tests/levels_menu_test.tscn`，应在隔离的用户目录中运行；覆盖真实鼠标输入、进度刷新和对应关卡加载，带画面运行时会输出 `.godot/levels_menu_qa/` 截图。

## 设置界面

`Interface/UI/Options.tscn` 的三个子菜单和各行均为手动定位的 `Control`，可直接在编辑器调整位置；内容默认字号为 26，控件页为 24。标签和操作控件向中间收拢，间距较大的行使用绿色虚线连接；`Setting_Connector.gd` 会随文字尺寸和控件位置自动重绘，编辑器中也可预览。控件页使用九项按键的两列五行布局，标签在左、按钮在右，Esc 保留为全局返回键。

游戏页的“全屏”立即切换窗口模式，重启后恢复；“跳过对话”默认不勾选，勾选后下次进入关卡不启动开场对话，并尊重 Game 原有的 `play_dialogue` 参数；“进度限制”默认勾选。三项偏好修改立即保存，主菜单与暂停菜单中的设置实例同步显示。

Godot 编辑器的嵌入式游戏窗口不支持全屏切换，此时仅保存全屏偏好。测试全屏时，在 Game 面板右上角菜单取消“Embed Game on Next Play”，停止后重新运行；独立窗口和导出游戏会应用该偏好。

每个按键的文字位于 `Content/Control/动作名/Key/Text`，不使用 Button.text。点击后等待一个键盘按键，期间清空当前键位文字，在 `Content/Control/BindingHint` 显示“请输入按键...”。有效输入立即保存并更新 InputMap，主菜单和暂停菜单实例同步显示；重启后恢复。重复使用的按键会交换两项操作的键位，左右 Shift / Ctrl / Alt / Meta 分别记录。Esc 保留为返回键，鼠标和按键重复不会参与绑定；切页、关闭或失焦取消未完成的改键，不改变已保存的设置。

键位回归入口为 `tests/key_bindings_test.tscn`，应在隔离的用户目录中运行。覆盖真实玩家移动、跳跃、无人机、图层与预览输入，以及冲突交换、旧存档迁移、损坏数据和写入失败；第二次启动追加 `-- --verify-persisted` 检查跨进程恢复。

重置按钮不显示文字，按住时 `Content/Game/Clear/Action/VisualRoot` 的位移和旋转抖动逐渐增强，默认最大位移幅度为 2 像素、旋转为 0.75°，下方的 `Clear/Progress` 显示绿色蓄力条。按住五秒蓄满后清空通关存档，保留偏好和当前运行关卡。按钮命中范围固定，松开、移出、切页或窗口失焦均会取消并复原。蓄力时长与抖动幅度可在 Options 根节点的检查器调整。

## 影子承影遮罩

保留原有每个投影物体的 `2n+1` 个 Shadow 节点和静止后的实体切割。GPU 保留全局 RGBA 承影覆盖纹理，并将已有 ShadowVisual 的投影绘制为分层遮罩；承影图层内部染黑 RGB、保留原 Alpha，避免半透明和模糊边缘的白边与背景重复压暗。空白和贴图镂空不显示影子。Level09～12 的雾改为黑色，避免将黑影染灰。

运行时可在 `Game/ShadowMaskSystem` 切换完整影子、正常裁切和覆盖图三个调试视图。架构、使用方式和回归测试见 [影子遮罩说明](./Logs/影子遮罩渲染_2026-10-17.md)。

布尔碎片保留原缩放与描边样式，实体、Shape、Outline、点选碰撞及 Shadow 母本使用一致轮廓，新切口也绘制闭合描边。纹理通过局部锚点补偿保持切割前后的图案连续，并随碎片移动与换层。

切割时为消失区域缓存一次局部 GPU 外观与覆盖遮罩，随后平滑淡出，保留区域不会重复叠加透明度。`Game/ShadowControllerSystem.cut_afterimage_duration` 默认 `0.2` 秒，设为 `0` 可关闭。残影跟随原图层的视差和轮换，不参与物理、点选或承影覆盖；游戏暂停时同步暂停。专项回归入口为 `tests/shadow_afterimage_test.tscn`。

第十二关月亮由 `Moon.gd` 独立管理视差和五点遮挡检测。`sample_distance` 是中心到上下左右四点的本地距离，默认 `108`，随精灵缩放；任一点露出就每帧调用 `SignalSystem.timer_reset()`，全部被挡住才允许原倒计时进入切割。检测读取实体、纹理透明度和残影，忽略背景、雾与界面；离屏点不算露出。GPU 局部覆盖压缩为五列结果后回读，到期帧等待本帧检测结果再结算。专项入口为 `tests/moon_visibility_test.tscn`。

黑夜关卡层使用低强度、大范围的原生 PointLight2D 头部光源，仅照亮关卡层实体，不叠加全屏空气效果。背景、其他图层和界面不受此灯光影响，跨层黑影保持纯黑。照明参数位于 Level 根节点，详见 [关卡层照明说明](./Logs/关卡层照明_2026-10-17.md)。

黑夜前景另用图层 Alpha 表面滤镜：轮廓及透明洞口在距人物头部 100 世界单位内最高保留正常景深配色的 75% 亮度，向外平滑衰减，700 单位外保留 20%，与内部暗区一致；新切口自动参与。参数位于 Level 的“黑夜前景表面”分组，默认亮带宽 4、过渡宽 2 屏幕像素，为初版的约八分之一；替代前景统一压暗，并在图层轮换中平滑过渡。详见 [黑夜前景表面说明](./Logs/黑夜前景表面_2026-10-19.md)。

## Ground 土壤贴图烘焙

项目包含编辑器插件 [Soil Baker](./addons/soil_baker/README.md)。在场景树选中 Ground 后，可以预览并生成独立的 `Soil_编号.tscn` 与 PNG。圆角、手绘描边、棕红底色和上缘绿色波点均在编辑阶段烘焙；游戏运行时直接读取保存的贴图。
