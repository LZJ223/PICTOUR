# 纵向试验：统一投影与局部撤回 · 2026-10-09

## 目标与范围

背景严格检查实体占用会保留空间决策，却可能让刚搬出的物件难以送回。本试验保留严格占用，并提供一次操作尺度的 `Z` 撤回：同时恢复该次成功搬运前的全部物件和玩家站位。它不是放宽背景重叠，也不是仅把选中物件移回去。

本功能只进入新的 `StudySystemController` 场景。旧庭园、旧白模和四层原型的背景豁免、书签、存档和输入保持原规则。没有新增永久奖励和磁盘存档。

## 纵向取景与解谜锚点

`SystemController.get_projection_anchor()` 是新的可覆盖接口，默认返回 `camera.global_position`，与之前相同。共享系统的图层投影、物件搬运、占用预检、旧组件形状查询和重置统一调用它。

研究场的覆盖函数返回 `Vector2(player.global_position.x, projection_anchor_y)`，默认 `projection_anchor_y=720`。玩家上楼或相机上下取景不会意外挪动背景的纵向解谜关系；改变水平站位仍能改变层间相对位置。非默认Y540也已验证。

Study取景另有导出参数：

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `view_follow_y` | true | 允许纵向跟随人物 |
| `view_use_deadzone` | true | 启用纵向死区；关闭可对照直接跟随 |
| `view_deadzone_y` | 65 | 视野中心上下各65px内不推动镜头 |
| `view_offset_y` | -150 | 画面中心位于人物上方 |
| `view_min_y` / `view_max_y` | 390 / 930 | 纵向取景边界 |
| `view_min_x` / `view_max_x` | 640 / 1600 | 横向取景边界 |

相机X可以被边界限制，投影X仍取真实玩家X。视觉和真正W/S使用同一锚点，不能拿屏幕相机位置单独计算搬运。相机和物件投影都在物理帧更新，没有改渲染频率、VSync、物理频率或插值设置。

纵向取景采用死区：细小坡面和普通跳跃的前段保持画面，人物持续越过边界后才把镜头推到相应边缘；落回死区内也不立即反向拉画面。没有新增显示帧平滑或改变物件视差。普通传送通过 `reset_view_interpolation()` 以新站位重建视野；整套撤回通过 `reset_restored_view_interpolation()` 从已保存相机高度重新建立死区缓存，保留操作前的构图。

## Z与R的事务范围

`StudySystemController` 自动创建 `TransferHistory` 子节点，类型为 `StudyTransferHistory`，无需放置旧 `BookmarkManager`。

- 每次搬运先拍摄完整内存状态，只有搬运成功才压入历史。失败W/S不产生记录，默认最多64条。
- 每条记录包含所有 `LayerObject` 的稳定ID、实例身份、固定 `layer_id`、世界根变换、`CollisionBox`变换（含真实尺度）、当时的碰撞形状；同时保存玩家根位置、碰撞尺寸、速度、方向、冲刺/跳跃缓存等运动状态，以及相机、相机跟随状态和投影锚点。
- `Z` 按键排队到物理帧执行。先检查整个快照的对象身份、数量、有限坐标、形状与根位一致性，然后以快照形状检查固定地形、同层物件及玩家占用；全部有效后才同步恢复。没有在恢复中途等待下一帧，也不把人物另送到一个“安全位置”来掩盖部分恢复。
- 恢复查询排除物件当前摆位，以保存的凸形状相互检查，避免当前物件挡住自己的旧位置。若新固定墙占据旧落点、对象缺失或记录无效，整套拒绝，世界与历史计数均不改变。
- 恢复每个物件的主碰撞后立即调用其投影更新，让 PaperStage/Vertical 直属物理体的额外轮廓先同步尺度；全部实体到位后才刷新人物接触缓存，最后统一重置插值历史。玩家可以撤回搬走脚下平台的动作，恢复物件及自己后实际站稳。
- 恢复后清理选中与待执行交互。角色视觉若提供公共 `reset_after_restore()` 就调用它重建足点与姿态缓存（供V6使用），V5保留旧位置缓存兼容处理；围巾另行调用 `reset_cloth()` 从恢复位置重新展开。
- `R` 恢复本研究场进入时的初始完整状态，并清空局部历史。初始投影锚点也恢复。它不读取旧庭园书签，不修改旧玩家存档，也不提供永久奖励回退。

需要留意：完整撤回会把人物带回操作发生时的站位。这个行为属于本轮明确的解谜取舍，避免只撤物件却把正在其上方或缝隙中的人物压入实体。

## 选中预览

研究场选中物件时，目标轮廓以绿色或红色表示是否可搬；失败时通过真实目标层的形状碰撞取得接触点，以橙色叉圈标出。背景目标碰撞点也按同一锚点投影回可见位置，避免出现“图上没有挡住、实际却失败”的两套判断。

轮廓只在选中时出现，不将整场景画成调试线。失败原因仍由原 `Global.transfer_result` 发送；纯花草无实体时不会制造虚假的阻挡标记。

## 关卡接口

- 脚本：`System/Study/Study_System_Controller.gd`，继承 `SystemController`。
- 节点引用仍为 `player`、`camera`、`level`。关卡明确配置两层、玩家槽位0、禁止整体轮换与无人机；`allow_scenery_overlap_outside_player_layer=false` 保留严格背景占用。
- 所有可辨认物件直接挂在 `DepthLayer` 下并设置唯一 `persistent_id`。本轮对象集合固定；增加或删除对象会使旧历史失效，避免半份恢复。
- 方法：`undo_transfer()`、`reset_study()`、`get_projection_anchor()`、`get_preview_state()`。
- 提示UI可连接 `system.history.history_changed(count)` 与 `system.history.message_changed(text)`。

## 验证结果

`Tests/Study_Transfer_Regression.tscn -- --v6` 在headless与Windows D3D12 GPU各90项全部通过，GPU错误日志为空，进程退出码均为0。覆盖固定/非默认投影锚点、65px死区与直接跟随对照、纵向镜头变化、真实W/S、失败碰撞预览、成功历史/失败不记、两次整套撤回、非法历史原子拒绝、新地形阻挡旧落点、真实Z/R、严格背景占用，以及搬走脚下平台后的人物与实体共同恢复。V5默认角色版本在headless完成84项；加入死区前的69项也曾通过GPU，未把该旧GPU结果当作新版84项结果。

多轮廓专项实际使用 `VerticalGardenObject` 的两个直属碰撞多边形：人物站在第二段踏面，物件搬远后真实放大至1.25，人物下落；Z恢复双方后第二段继续真实承托人物。R也从该缩放状态恢复原尺度与初始玩家位置。检查直接读取 `PhysicsServer2D.body_get_shape_transform`，不以手动查询或只恢复主轮廓代替真正实体验证。

V6另检验小于100px的撤回不会留下未来世界足锚、旧姿态和错误朝向。`Tests/Study_Transfer_V6_Bookmark.tscn` 使用真正Story/V6与书签管理器，headless22项通过：从近处真实按R、按M后点击起点书签，在恢复信号中检查足锚、姿态前后缓存、朝向、零速度与围巾原点，再检查真实站稳。其存档路径在进入树前覆盖为独立 `user://Tests/Study_Transfer_V6_Bookmark.json`，测试结束已清理；未运行该独立书签专项的GPU版。

`Tests/Study_Transfer_Level_Check.tscn` 使用实际 `Vertical_Garden_Game` 三件成图物件与地貌，headless/GPU各25项通过：先走到x480搬近垂腹枝，再走到x290送远卷根门，继续行走后两次Z恢复，最后R还原全场；所有直属实体分块尺度与实际人物落脚正常。真实约108px完整跳跃在死区内的上升阶段不推动镜头，全程取景位移小于45px；R恢复初始视野，随后物理帧没有旧缓存拉回。

共享接口还运行旧 `Natural_Return_Regression`（172项）与 `Prologue_Regression`（130项），全部通过；这包含既有两层/四层场景的占用与搬运、旧能力检查，确认旧默认锚点行为未改变。
