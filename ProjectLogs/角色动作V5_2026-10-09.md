# 角色动作 V5：十六帧与坡面适配

日期：2026-10-09。目标是响应 C 方案角色在斜坡与跑步时生硬的反馈。独立增加 V5，不修改 V4、共享 `Player_Controller.gd` 或主入口；关卡接入由主 agent 与关卡 agent 协调。

## 根因与选择

V4 只按水平位移推进步态，无法表达斜面真实行程；默认约 1px 地面吸附在下坡和折点缺少余量。角色矩形碰撞在坡上由高侧角承重，平面位图两只脚无法同时贴住坡面。8 张姿态在现有速度下只提供约 13.3/16.8 张可见走/跑相位每秒，且走跑图组直接交替。

V5 采用两张独立 AI 生成的 16 姿态母图，保留 C 身份。它们确实不是重复 V4 帧，但生成结果并非严格动画师绘制的等时序周期；已按可见腿姿重排，仍需用户观察自然度。没有将 AI 图片称为手工原画。

## 实现

- V5 场景保留 180/320/560 速度、30×86 实体及约 108.6px 满跳；局部地面吸附 8px 与坡面恒速。
- 动画消耗真实坡面行程，起步选择较窄经过姿，走跑保持同一周期相位并在过渡窗口交接。没有透明混合两套腿姿。
- 原 PNG 无改写。AtlasTexture 保存真实裁切区域，原位图在细分网格上显示。身体整体竖直，仅小腿局部适应脚下高度；上身倾身约束在约 3° 范围。地面射线使用当前玩家掩码并排除自身。
- 换图会改变脚的横向坐标，若继续缓动旧图的脚高，会产生 4–7px 短暂穿坡；现在新脚高直接匹配当前地面，重心和上身仍平滑插值。
- 围巾保持独立受约束布料，领口来自每张图片的实际锚点；没有移动图层物理坐标或相机。

实现入口及资产细节见 [V5 README](../Art/Player/V5/README.md)。[Godot 官方 CharacterBody2D 文档](https://docs.godotengine.org/en/stable/classes/class_characterbody2d.html)说明，坡面恒速需搭配地面吸附；向上运动时吸附不应阻止主动跳跃。本轮依据该行为设置局部场景参数，并以真实坡面运行验证。

## 验证与边界

验证以 `Art/Player/V5/Traveler_V5_Check.tscn` 为入口，覆盖原始资源与不重复帧、0°/±18°/±28°双向走/跑、坡面行程、直立姿态、腾空、跳跃和当前层过滤。另运行 D3D12 Mobile 真实 GPU 动作场 480 物理帧，并保存平地与正负坡面对照录像。最终有效断言数量与坡顶/边缘补充结果在本条目末尾记录。

头less足点误差是代码查询与实际贴地网格坐标之间的误差，不能代替逐帧观看原图脚形、动画节奏和人物吸引力。尚未解决 AI 母图中相似姿态、支撑脚横向滑动及衣摆间歇变化；这类问题需经过用户审阅后针对性补绘。未声称已完成最终动画或 Windows 导出打包。

最终结果：`Traveler_V5_Check.tscn` 114 项、0 失败；包含坡顶接平地再下坡全程无意外起跳，以及台阶边缘无假地面。满跳保留约 108.6px，0°/±18°/±28°双向行走与跑步均连续贴地。D3D12 GPU 480 帧无脚本/渲染错误，透明图无矩形底。MP4 已验证首、中、末帧均可解码。

额外曾用 `--time-scale 4` 尝试缩短回归耗时，但此选项改变物理步长，不是等价加速：该探测运行出现 4 项失败（坡面距离误差、28°跑步失地、跳高变成124px和坡顶2帧离地）。未修改断言掩盖结果，默认60Hz重新执行后114项通过，最终日志为 `Exports/Traveler_V5_Check_Final.log`。本轮不引入游戏时间倍率功能，也不宣称支持4倍物理步长。
