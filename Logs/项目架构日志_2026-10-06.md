> 记录日期：2026-10-06  
> 项目引擎：Godot 4.7 系列  
> 记录范围：`project.godot`、GDScript 脚本与场景文件  
> 排除范围：策划案、`.godot` 缓存、`.uid` 资源标识文件

## 1. 项目概况

PICTOUR 当前是一个以二维物理世界为基础、通过视觉代理表现多深度图层的白模项目。项目将“物理状态”和“屏幕表现”分开：物体根节点负责真实位置及碰撞，物体下的 `VisualRoot` 根据相机锚点和图层槽位单独计算显示位置、显示比例与绘制顺序。

当前实现包含四个内容层和四个显示槽位。内容层由固定的 `layer_id` 标识，显示槽位由可轮换的 `slot` 标识。图层轮换只改变各内容层占据的显示槽位；玩家则通过切换自身的碰撞层与当前活动内容层保持一致。

## 3. 运行入口与总场景

`project.godot` 将 `Prototype_Game.tscn` 设置为主场景，并把 `System/Global.gd` 注册为自动加载单例 `Global`。

主场景结构如下：

```text
Prototype_Game（Node2D）
├─ Level（Prototype_Level 实例）
├─ Player（Player 实例，CharacterBody2D）
├─ Camera（Camera2D）
└─ System（Node + SystemController）
```

各节点职责：

- `Level` 保存全部内容层及关卡物体。
- `Player` 是唯一直接接收移动输入的玩家控制体。
- `Camera` 不挂在玩家或视觉节点下，由系统每帧同步到玩家世界坐标；当前有 `(0, -180)` 的画面偏移。
- `System` 持有玩家、相机和四个图层的显式引用，负责系统间协调。

主场景中玩家初始位置为 `(668, 330)`，初始碰撞层和碰撞遮罩均为物理位 `2`。

## 4. 图层模型

### 4.1 内容层与显示槽位

每个 `DepthLayer` 同时具有两个身份：

| 字段 | 含义 | 是否随轮换变化 |
|---|---|---|
| `layer_id` | 内容层固定编号，也是该层物理碰撞位的依据 | 否 |
| `slot` | 当前占据的视觉深度槽位 | 是 |

当前槽位定义来自 `Depth_Layer.gd`：

| slot | 枚举名 | 显示倍率 | VisualRoot z_index |
|---:|---|---:|---:|
| 0 | `FRONT` | `1 / 0.75 ≈ 1.3333` | 400 |
| 1 | `CURRENT` | `1.0` | 300 |
| 2 | `MIDDLE` | `0.75` | 200 |
| 3 | `BACK` | `0.75² = 0.5625` | 100 |

其中 `CURRENT（slot 1）` 是玩家常规活动的视觉基准面。`layer_id` 和 `slot` 初始均覆盖 `0～3`，但两者在图层轮换后不再相同。

### 4.2 单层场景结构

```text
Layer（Node2D + DepthLayer）
├─ Ground（StaticBody2D + Ground）
│  ├─ CollisionPolygon2D                 # 固定物理碰撞
│  └─ VisualRoot（Node2D）
│     └─ Polygon2D                       # 地面视觉
└─ 其他 LayerObject 实例                 # Box、Goal、PlayerObject 等
```

`DepthLayer._ready()` 将自身加入 `depth_layers` 组并应用初始槽位状态。`SystemController` 随后在每个渲染帧中调用所有图层的 `apply_slot_state()`，以玩家世界位置作为视觉锚点。

### 4.3 图层轮换

全局输入发出 `Global.layer_cycle(direction)` 后，`SystemController.cycle()` 对每个内容层执行：

```text
new_slot = posmod(old_slot + direction, layer_count)
```

因此四个内容层会循环占据四个槽位。系统在初始化和每次轮换后检查槽位唯一性，确保不存在两个内容层占据同一槽位。

图层轮换的职责边界如下：

- 内容层的固定 `layer_id` 不变。
- 图层根节点及物体的真实物理位置不因轮换而改变。
- `slot`、视觉倍率、视觉偏移和绘制顺序发生变化。
- 玩家同步切换自己的碰撞 layer/mask，使其只与当前活动内容层交互。

## 5. 物体模型

### 5.1 抽象基类 `LayerObject`

`LayerObject` 是抽象类，继承自 `PhysicsBody2D`。所有属于内容层的物理物体均通过它统一管理图层归属和图层转换。

核心数据：

| 字段 | 类型 | 作用 |
|---|---|---|
| `object_id` | `int` | 物体标识，当前默认值为 0 |
| `can_transfer` | `bool` | 是否允许主动转换内容层 |
| `size_step` | `int` | 物体实际尺寸的离散等级 |
| `owner_layer` | `DepthLayer` | 当前所属内容层的运行时引用 |

初始化流程：

1. 加入 `layer_objects` 组。
2. 向上查找所属 `DepthLayer`。
3. 根据 `size_step` 设置初始根节点比例。
4. 根据所属层当前槽位设置初始碰撞组。

抽象接口：

```gdscript
apply_visual_transfer(anchor_position, slot)
set_collision_group(old_group, new_group)
set_scaling(scaling)
set_pick_condition(condition)
```

子类负责决定实际视觉节点、碰撞节点以及是否响应缩放和选取。新增图层物体时应继承 `LayerObject` 并完整实现以上接口。

### 5.2 物理与视觉分离

可交互物体遵循以下结构：

```text
PhysicsBody2D + LayerObject 子类          # 真实位置、速度和实体碰撞
├─ CollisionBox / CollisionPolygon2D      # 实体碰撞形状
└─ VisualRoot（Node2D）                   # 屏幕表现代理
   ├─ Line2D                              # 选中轮廓
   ├─ Polygon2D                           # 白模外观
   └─ Area2D
      └─ CollisionShape2D/Polygon2D       # 鼠标点选区域
```

`VisualRoot` 的局部变换由槽位倍率决定。设物体真实世界坐标为 `P`、玩家锚点为 `A`、槽位显示倍率为 `s`：

```text
VisualRoot.scale    = actual_scale × s
VisualRoot.position = (A - P) × (1 - s)
最终显示坐标         = A + (P - A) × s
```

这使物理根节点保留在静态世界坐标中，而画面上的物体相对玩家产生近大远小和差速位移。选取用的 `Area2D` 位于 `VisualRoot` 下，因此点选区域会与画面表现同步；实体碰撞形状则直接位于物理根节点下。

### 5.3 主动物体图层转换

当选中物体后，Q/E 不再轮换整个图层，而是请求选中物体向相邻槽位转换。当前计算过程为：

1. 读取物体所属层的旧 `slot`。
2. 计算 `new_slot = old_slot - direction`；越界则取消。
3. 根据新槽位找到目标内容层。
4. 将物体重设父节点到目标内容层。
5. 使用 `old_scale / new_scale` 计算位置换算比例。
6. 以玩家位置为锚点重新计算物体真实位置。
7. 更新 `size_step`、实体碰撞尺寸和碰撞组。
8. 更新 `owner_layer`。

位置换算公式为：

```text
ratio = layer_scales[old_slot] / layer_scales[new_slot]
new_position = anchor + (old_position - anchor) × ratio
```

实际尺寸等级使用固定倍率 `0.75`：

```text
actual_scale = 0.75 ^ size_step
```

## 6. 具体对象

### 6.1 `Box`

- 根节点：`RigidBody2D`。
- 用途：受物理模拟影响、允许跨层转换的方块。
- 实体碰撞：根节点下的 `CollisionBox`。
- 显示与选取：`VisualRoot` 下的多边形、轮廓线和 `Area2D`。
- 缩放实现：改变实体 `CollisionBox.scale`；视觉倍率在下一次视觉刷新时由碰撞比例和槽位倍率共同计算。
- 碰撞组实现：同时切换 collision layer 与 collision mask。

### 6.2 `Ground`

- 根节点：`StaticBody2D`。
- `can_transfer = false`，不能主动跨层。
- 实体碰撞始终保持原始尺寸。
- 仅 `VisualRoot` 随槽位改变视觉比例和位置。
- 只设置 collision layer，不设置 collision mask。
- 选中与实际缩放接口为空实现。

### 6.3 `Goal`

`Goal.gd` 定义了与 `Box` 相同的视觉、碰撞组、尺寸和选中接口，计划作为独立的 `LayerObject` 类型使用。当前场景引用情况见“当前实现注意事项”。

### 6.4 `Player_Object`

- 根节点：锁定旋转的 `RigidBody2D`。
- 用于无人机模式开启时，在当前内容层中保留玩家原身体的实体状态。
- 结构和接口与一般可选取图层物体一致。
- `SystemController` 会在退出无人机模式时读取其所属层、位置和碰撞尺寸，并据此恢复可操作玩家。

## 7. 玩家系统

`PlayerController` 继承 `CharacterBody2D`，内部同时保存人物形态和无人机形态的碰撞与视觉节点。

### 7.1 常规状态

- A/D 控制水平移动。
- Space 在接地时跳跃。
- 未接地时施加重力。
- 水平速度使用加速度、摩擦减速度和最大速度共同限制。
- 最终统一调用 `move_and_slide()`。

### 7.2 无人机状态

- 人物碰撞和外观关闭，无人机碰撞和外观开启。
- A/D 控制水平移动，W/S 控制垂直移动。
- 切换形态时速度清零。
- 无人机启用时，系统在当前 `slot 1` 的内容层生成 `Player_Object`，保存人物原身体。
- 无人机关闭时，系统轮换图层直到该实体回到 `slot 1`，随后恢复玩家的位置和比例并删除临时实体。

### 7.3 玩家碰撞面切换

玩家记录当前 `collision_group`。图层轮换时，根据方向计算新的碰撞位：

```text
new_group = posmod(old_group - direction - 1, layer_count) + 1
```

旧 collision layer/mask 被关闭，新 collision layer/mask 被开启。内容层物体的碰撞位依据固定 `layer_id + 1` 设置，因此玩家碰撞位的轮换等价于切换当前可交互的内容层。

## 8. 全局输入、状态与信号

`Global.gd` 同时承担配置、输入解析、选取状态和事件总线职责。

### 8.1 全局配置

```text
layer_count = 4
layer_scale = 0.75
layer_scales = [1.3333, 1.0, 0.75, 0.5625]
```

### 8.2 全局状态

| 状态 | 含义 |
|---|---|
| `object_selected` | 当前鼠标选中的 `LayerObject`，未选中时为 `null` |
| `UAV_activated` | 无人机模式是否激活 |

### 8.3 信号

| 信号 | 发送条件 | 主要接收者 |
|---|---|---|
| `layer_cycle(direction)` | 未选中物体时按 Q/E | `SystemController`、`PlayerController` |
| `layer_change(direction, object)` | 已选中物体时按 Q/E | `SystemController` |
| `UAV_activate(status)` | 按无人机切换键 | `SystemController` |

### 8.4 鼠标选取

鼠标左键触发一次物理点查询，只检测 `Area2D`。查询结果按照碰撞体的 `z_index` 选择最前方对象，再向上查找第一个 `LayerObject`。选中变化时，旧对象关闭轮廓，新对象显示轮廓。

## 10. 原型关卡组成

`Prototype_Level.tscn` 实例化四个 `Layer`：

| 内容层 | layer_id | 初始 slot | 初始对象 |
|---|---:|---:|---|
| `Layer0` | 0 | 0 | 1 个 Box、Ground |
| `Layer1` | 1 | 1 | 1 个 Box、Ground |
| `Layer2` | 2 | 2 | 2 个 Box、1 个 Goal、Ground |
| `Layer3` | 3 | 3 | 2 个 Box、Ground |

每层通过覆盖 `Ground/VisualRoot/Polygon2D` 的颜色形成深度区分。所有图层根节点当前都保持默认位置和比例，因此跨层 `reparent(..., false)` 后仍能沿用同一套局部坐标计算。

## 11. 主要运行时流程

### 11.1 每帧视觉刷新

```text
SystemController._process
├─ Camera.global_position ← Player.global_position
└─ 遍历所有 DepthLayer
   └─ 遍历层内对象
      └─ apply_visual_transfer(Player.global_position, layer.slot)
```

### 11.2 整体图层轮换

```text
Q/E 输入
→ Global.layer_cycle
├─ SystemController：轮换所有 DepthLayer.slot
└─ PlayerController：切换玩家 collision layer/mask
→ 下一帧按新槽位刷新全部 VisualRoot
```

### 11.3 单个物体转换

```text
鼠标选择对象
→ Q/E 输入
→ Global.layer_change
→ SystemController 查找目标槽位对应的内容层
→ LayerObject.transfer_to
   ├─ reparent
   ├─ 换算真实位置
   ├─ 更新 size_step 与碰撞尺寸
   ├─ 更新碰撞组
   └─ 更新 owner_layer
```

### 11.4 无人机切换

```text
无人机键
→ Global 切换 UAV_activated
→ SystemController
├─ 通知 PlayerController 切换形态
└─ 开启：在 CURRENT 层生成 Player_Object
   关闭：轮换至 Player_Object 回到 CURRENT 层，恢复玩家后删除临时实体
```

## 12. 协作与扩展约定

### 12.1 新增普通图层物体

1. 根节点使用合适的 `PhysicsBody2D` 子类。
2. 脚本继承 `LayerObject`。
3. 实体碰撞形状直接放在物理根节点下。
4. 外观和点选 `Area2D` 放入 `VisualRoot`。
5. 实现四个抽象接口。
6. 将实例直接放在某个 `DepthLayer` 下，保证能够向上找到所属层。

### 12.2 新增内容层

当前系统的层数、显示倍率数组、碰撞位计算和槽位断言均以 `Global.layer_count = 4` 为基础。调整层数时必须同步检查：

- `Global.layer_scales` 的元素数量；
- `DepthLayer` 的槽位枚举和 `set_slot()` 边界；
- 主场景 `System.layers` 引用数组；
- 关卡中的 `layer_id` 与初始 `slot` 唯一性；
- Godot collision layer/mask 的对应物理位；
- 玩家碰撞组轮换公式。

### 12.3 场景组织约束

- 内容层根节点应保持相同的空间变换，否则当前跨层重设父节点方式会改变物体语义位置。
- `DepthLayer` 的直接子节点当前应当都是实现了 `apply_visual_transfer()` 的图层对象。
- `VisualRoot` 只处理显示和点选代理；会参与运动解算的实体碰撞应留在物理根节点下。
- 相机由 `SystemController` 独立跟随玩家，不应成为任何深度视觉节点的子节点。
- 图层固定身份使用 `layer_id`，视觉状态使用 `slot`，协作时不要混用两者。

## 13. 当前实现注意事项

以下内容是从当前场景和脚本引用关系中得到的现状记录，供协作者在继续开发前核对；本文不对项目文件作任何修改。

1. `Goal.tscn` 当前引用的是 `Component/Object/Box/Box.gd`，根节点名称也是 `Box`；`Goal.gd` 没有被该场景引用。因此关卡中的 Goal 实例当前实际按 `Box` 类型运行。
2. `Box.tscn` 将 `object_id`、`can_transfer`、`size_step` 显式保存为 `null`。这些字段在脚本中分别声明为 `int`、`bool`、`int`，协作者应在编辑器中确认当前 Godot 版本对这些覆盖值的实际解释。
3. `DepthLayer.apply_slot_state()` 使用 `child is Object` 作为直接子节点筛选条件。由于 Godot 节点均属于 `Object`，当前实现实际会对每个直接子节点调用 `apply_visual_transfer()`；因此暂时不能在层根节点下直接加入未实现该方法的普通节点。
4. `LayerObject._ready()` 会设置物理根节点的初始 `scale`，后续 `set_scaling()` 则由现有子类修改实体碰撞节点的比例。若关卡预设非零 `size_step`，需要确认初始化比例与运行时转换比例是否符合预期。
5. 鼠标选取依赖 `VisualRoot` 下 `Area2D` 的 `z_index`。新增可选取对象时需要保持选取区域与视觉层级同步。
6. `SystemController` 的 `layers` 数组依赖主场景中的手动 NodePath 配置；增删或重命名图层后需要同步更新该数组。
