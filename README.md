# PICTOUR

PICTOUR 是一款使用 Godot 4 开发的 2.5D 平台跳跃解谜游戏。项目将透视中的“近大远小”、多层视差和前后遮挡转化为可操作的解谜规则。

玩家可以转换单个物体的图层、轮换整个场景的图层，也可以使用无人机改变视角锚点。不同操作会分别改变物体的实际尺寸、画面尺寸与相对位置。

当前项目处于核心机制验证和白模关卡开发阶段。

## 核心玩法

场景由四个景深槽位组成：

| 槽位 | 显示倍率 | 说明 |
|---|---:|---|
| 前景层 `FRONT` | 约 1.3333 | 位于玩家前方，可产生近景遮挡 |
| 关卡层 `CURRENT` | 1.0 | 玩家或当前控制主体所在层 |
| 中景层 `MIDDLE` | 0.75 | 玩家后方的主要交互层 |
| 后景层 `BACK` | 0.5625 | 最远的可见交互层 |

相邻图层统一使用 `0.75` 倍率。

三个核心操作分别是：

- **转换物体图层**：保持物体换层瞬间的画面大小和画面位置，改变其实际尺寸、真实位置与碰撞层。
- **轮换整体图层**：保持物体实际尺寸和真实物理状态，改变其画面大小、视差速度、遮挡关系及玩家当前可碰撞的内容层。
- **使用无人机**：把视角锚点从人物转移到无人机，使人物成为视差系统中的普通物体。

简要记忆：**换物体，改变实际；换图层，改变画面；换锚点，让人物进入透视系统。**

## 关卡方向

- **森林**：物体尺寸变化与横向视差对齐。
- **城市**：利用无人机改变观察位置，在纵向空间中调整人物与平台的位置关系。
- **工厂**：计划通过跨层光源、投影和轮廓布尔运算改变物体形状。

工厂光影系统属于后续设计方向，当前白模尚未实现完整功能。

## 环境要求

- Godot `4.7.2-stable`
- Windows 开发环境
- 项目设计分辨率：`1280 × 720`
- 当前渲染模式：Mobile

项目使用的 Godot 可执行文件：

```text
C:\Program Files\Godot\Godot_v4.7.2-stable_win64.exe
```

## 打开并运行项目

### 使用 Godot 项目管理器

1. 启动 Godot 4.7.2。
2. 点击“导入”。
3. 选择 `PICTOUR/project.godot`。
4. 导入并打开项目。
5. 按 `F6` 运行当前场景，或按 `F5` 运行主场景。

主场景为：

```text
Prototype_Game.tscn
```

## 当前操作

| 操作 | 默认输入 |
|---|---|
| 左右移动 | A / D |
| 跳跃 | Space |
| 无人机上下移动 | W / S |
| 正向图层操作 | Q |
| 反向图层操作 | E |
| 选择物体 | 鼠标左键 |
| 开启或关闭无人机 | Page Up |

Q/E 的行为取决于当前是否选中了物体：

- 未选中物体：轮换全部内容层。
- 已选中物体：只将选中物体向相邻图层转换。

鼠标再次选择其他物体时，原物体会取消选中。带有选中轮廓和点选区域的物体才能参与该操作。

## 架构概览

主场景由关卡、玩家、相机和系统控制器组成：

```text
Prototype_Game
├─ Level
│  ├─ Layer0
│  ├─ Layer1
│  ├─ Layer2
│  └─ Layer3
├─ Player
├─ Camera
└─ System
```

每个内容层使用固定的 `layer_id` 表示身份，并使用运行时可变的 `slot` 表示当前画面深度。整体轮换只改变内容层占据的槽位，不改变内容层身份。

普通图层物体采用物理与视觉分离的结构：

```text
PhysicsBody2D
├─ 实体碰撞                     # 真实世界中的碰撞
└─ VisualRoot
   ├─ 画面外观
   ├─ 选中轮廓
   └─ Area2D                    # 鼠标点选区域
```

物理根节点保存真实位置和物理状态，`VisualRoot` 根据视角锚点和槽位倍率计算画面位置、比例与绘制顺序。图层视差只改变画面表现，不应持续推动实体物理世界。

## 制作新关卡

推荐以 `Level/Prototype_Level.tscn` 为模板：

1. 复制原型关卡并保存为新的 `.tscn` 文件。
2. 保留 `Layer0`、`Layer1`、`Layer2`、`Layer3` 四个内容层。
3. 保持四层的 `layer_id` 和初始 `slot` 分别为 `0～3`。
4. 将 Ground、Box、Goal 等物品直接放在目标 Layer 下。
5. 只移动物品根节点，不要手动移动或缩放 `VisualRoot`。
6. 不要手动修改物品的 collision layer 或 collision mask。
7. 运行关卡并验证四层轮换、物品选择、跨层转换和刚体稳定性。

新关卡建议命名为：

```text
Level_01_Introduction.tscn
Level_02_Alignment.tscn
Level_03_UAV.tscn
```

当前玩家出生点不属于 Level 场景，主场景也没有自动关卡加载器。新关卡测试时，需要复制 `Prototype_Game.tscn` 建立独立测试场景，替换其中的 Level 实例，并设置玩家出生位置。

完整流程与检查清单请阅读[关卡设计与协作指南](./ProjectLogs/关卡设计与协作指南_2026-10-06.md)。

## 增加物品

### 增加已有物品实例

将对应场景从 `Component/Object/` 拖入目标 Layer，然后修改物品根节点的位置即可。

例如：

```text
Component/Object/Box/Box.tscn
Component/Object/Ground/Ground.tscn
Component/Object/Goal/Goal.tscn
```

### 增加新的物品类型

新的公共物品类型应放在独立目录中：

```text
Component/Object/NewObject/
├─ NewObject.tscn
└─ NewObject.gd
```

图层物品脚本应继承 `LayerObject`，并实现以下能力：

- 根据槽位刷新画面位置和尺寸；
- 设置所属内容层的碰撞关系；
- 响应实际尺寸变化；
- 设置选中反馈。

新物品至少应区分实体碰撞与 `VisualRoot`。如果允许鼠标选择，还需要在 `VisualRoot` 下提供与画面同步的 `Area2D` 点选区域。

关卡策划需要新增物品时，应先说明物理类型、能否选择、能否换层、是否受重力、触发条件和预期反馈，再由程序制作可复用组件。

- 四个内容层和四个显示槽位；
- 以 `0.75` 为相邻层倍率的视觉缩放和视差；
- 整体图层循环轮换；
- 玩家碰撞层随当前活动内容层切换；
- 鼠标点选图层物体；
- 单个物体跨相邻层转换；
- 方块刚体、地面和基础目标物体；
- 玩家移动、跳跃与无人机形态切换；
- 基础原型关卡。

尚未完成或需要确认：

- 自动关卡加载、关卡选择和统一出生点数据；
- Goal 的正式通关判定；
- 工厂章节的投影与轮廓布尔运算；
- 正式美术、声音、界面和完整反馈；
- 软锁恢复、关卡重置和存档流程；
- `Goal.tscn` 当前仍引用 Box 脚本，需要在正式使用前修正；
- `Box.tscn` 中部分导出字段当前保存为 `null`，需要确认默认值行为。

## 协作注意事项

- 关卡物品必须直接放在 `Layer0～Layer3` 之一的下面。
- Layer 的直接子节点暂时只能放标准图层物体，不要放普通辅助节点。
- 不要为了单个关卡直接修改 `Component/` 中的公共场景。
- 地形外观变化时，需要同步修改实体碰撞轮廓。
- 刚体初始位置不能与地面或其他刚体重叠。
- 图层固定身份使用 `layer_id`，画面深度使用 `slot`，不要混用。
- 调整图层数量、倍率或碰撞位属于系统级改动，需要同步检查所有关卡。
- 对公共组件的修改可能影响全部关卡，提交前应完成完整回归测试。
