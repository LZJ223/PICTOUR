# PICTOUR 开发日志｜2026-10-09

## 今日概览

今天的主要工作是完成影子生成与管理逻辑，并打通“停止操作——触发切割——生成新物体”的基础流程。与 10 月 7 日只完成影子几何和视觉验证的状态相比，当前影子已经能够根据物体所在图层动态启用，并在静止一定时间后对后方物体进行布尔差集切割。

同时，原本集中在 `Global` 和 `SystemController` 中的职责被拆分为全局数据、信号输入、图层控制和影子控制四个部分，为后续继续扩展影子机制留出了比较清晰的系统边界。

> 今日工作尚未形成新的 Git commit，本日志以当前工作区中的实际代码和场景配置为准。

## 一、影子生成与管理逻辑

### 1. 统一影子能力数据

`LayerObject` 新增了两个可配置的能力开关：

- `can_leave_shadow`：物体是否可以向后方投射影子；
- `can_be_shadowed`：物体是否可以被影子切割。

同时，影子几何、画面表现与激活状态被统一保存在抽象物体中：

```text
shadow_box      影子在目标层中的几何基准
shadow_visual   经过景深换算后的画面影子
shadow_active   各目标层影子是否生效
```

这些数据下沉到 `LayerObject` 后，影子控制器可以直接统一查询投影物体，不需要依赖具体子类。

### 2. 按目标图层预生成影子池

`ShadowedGeometry` 在初始化时，不再只根据物体的初始位置生成影子，而是统一为下面的所有可能承影层建立影子实体：

```text
current_layer_index + 2 ... layer_count - 1
```

每个目标层同时保存一个 `shadow_box` 和一个 `shadow_visual`，并使用下式计算数组索引：

```text
index = target_layer - current_layer_index - 2
```

初始生成的影子全部处于关闭状态，之后只修改可见性和变换，避免物体换层时重复创建、删除影子节点。

### 3. 图层变化时动态启用影子

物体初始化、主动换层或整体图层轮换后，都会调用 `update_layer_slot()`。影子的启用条件为：

```text
投影物体位于关卡层之后
且
投影物体位于目标承影层之前
```

不满足条件的影子保持隐藏；满足条件时，才会在每帧更新几何与画面位置。这解决了旧方案在图层轮换后可能出现的影子数量不足或残留问题。

### 4. 影子几何与视觉保持分离

影子仍然使用两套变换：

- `shadow_box` 记录用于布尔运算的实际投影轮廓；
- `shadow_visual` 根据目标层缩放比例显示在画面中。

当玩家或视角移动时，系统使用投影物体和承影层的缩放比例，分别更新两组影子的位置与尺寸。布尔运算只读取 `shadow_box`，不受最终画面缩放影响。

## 二、静止后触发影子切割

`Signal.gd` 中增加了一个单次计时器，当前等待时间为 `2.0` 秒。以下行为会重置计时：

- 整体图层轮换；
- 鼠标选取物体；
- 当前存在被选中的物体；
- 玩家或无人机正在移动。

计时结束后，系统会暂停 `PhysicsServer2D`，然后发出 `shadow_boolean` 信号。下一次操作重置计时器时，物理服务器会重新启用。

这使布尔运算不需要每帧执行，也避免了计算时刚体仍在移动导致的结果不稳定。

## 三、分层布尔切割流程

### 1. 按承影层独立计算

`ShadowControllerSystem` 从最后一层开始，向前处理到关卡层后的第二层：

```text
layer_count - 1 ... current_layer_index + 2
```

对于每个目标层，会分别完成：

1. 扫描关卡层与目标层之间的全部图层；
2. 收集具有 `can_leave_shadow` 且当前激活的影子；
3. 将影子多边形转换到世界坐标；
4. 扫描目标层中具有 `can_be_shadowed` 的物体；
5. 计算物体轮廓减去所有影子后的结果；
6. 先保存切割计划，再统一替换节点。

“先计算、后修改场景树”避免了遍历目标图层时删除原物体导致的迭代问题。

### 2. 多影子差集

对于单个承影物体，所有影子会依次应用到当前剩余碎片上。每次差集前先比较物体碎片与影子的包围矩形；只有包围矩形相交时，才调用 `Geometry2D.clip_polygons()`。

运算后会过滤下面的无效结果：

- 顶点数少于 `3` 的退化多边形；
- 面积小于 `4.0` 的微小碎片。

系统最后通过切割前后的总面积判断物体是否真正发生变化，当前允许的面积误差为 `0.01`。

### 3. 孔洞结果保护

当影子完全包含在物体内部时，差集可能同时返回外轮廓和孔洞轮廓。当前通过检查顶点绕序识别这类结果。由于现有 `CollisionPolygon2D` 结构不能直接表示带孔多边形，遇到该情况时会放弃当前影子的切割结果，保留上一步的几何。

## 四、布尔结果的物体重建

当切割结果与原物体面积不同时，系统会根据原物体的 `scene_file_path` 重新实例化同类型场景。每个连通的差集结果都会生成一个独立新物体。

新物体会同步更新：

- `CollisionBox` 的实际碰撞轮廓；
- `VisualRoot/Polygon2D` 的白模外观；
- `Line2D` 的选中描边；
- `Area2D` 中的鼠标点选轮廓；
- `Shadow` 模板的后续投影轮廓。

新物体还会继承原物体的换层、投影和承影能力，并在白模阶段复制原外观颜色。所有有效碎片创建完成后，原物体会被加入释放队列。

如果原场景结构不满足碎片生成要求，且没有成功创建任何碎片，系统会保留原物体，避免因配置错误直接丢失关卡内容。

## 五、系统职责拆分

为了避免影子切割代码继续堆积在原 `SystemController` 中，今天将系统整理为：

| 脚本 | 当前职责 |
|---|---|
| `Global.gd` | 保存图层参数和场景节点，提供图层查询 |
| `Signal.gd` | 处理输入、全局信号、物体选取和静止计时 |
| `Layer_Controller_System.gd` | 更新视角、轮换图层、处理物体换层 |
| `Shadow_Controller_System.gd` | 收集影子、执行差集、重建物体 |
| `Player_Controller.gd` | 管理玩家移动和无人机状态切换 |

`LayerControllerSystem` 在 `_ready()` 阶段调用 `Global.discover_scene_nodes()`，并将当前场景根节点传入。因此，菜单等非关卡场景只要不挂载该控制器，就不会强制查找 `Level`、`Player` 和 `Camera`。

## 六、原型关卡验证内容

当前 `ShadowedGeometry` 同时启用了 `can_leave_shadow` 和 `can_be_shadowed`，因此既可以投射影子，也可以被前方物体的影子切割。

原型关卡中目前放置了三个 `ShadowedGeometry` 实例：

- `Layer2` 中一个；
- `Layer3` 中两个。

该布置可以验证单个投影物体、多个承影物体，以及切割后的新物体继续参与影子系统的情况。

## 八、当前边界与下一步

1. **带孔多边形**：当影子完全位于物体内部时，当前会跳过该次切割。后续需要加入三角化或凸多边形分解。
2. **贴图与 UV**：新碎片目前只复制白模颜色，尚未保留原物体的贴图映射。正式美术阶段需要根据原物体局部坐标生成 UV 或蒙版。
3. **碎片物理状态**：目前未显式继承原刚体的速度、质量和其他运行时参数，需要根据最终玩法决定是否按碎片面积分配。
4. **坐标转换**：当前原型的 `DepthLayer` 保持单位变换，因此碎片世界坐标可以直接用作图层局部坐标。如果后续对图层根节点增加位移、缩放或旋转，碎片生成时需要显式调用 `to_local()`。
5. **复合情况验证**：后续应补充多影子重叠、多次连续切割、图层轮换后切割和物体完全被切除等测试。

当前阶段已经建立了影子切割玩法所需的基础技术闭环。下一阶段的重点将从“让流程跑通”转向边界几何处理、贴图保留和复合关卡情况验证。
