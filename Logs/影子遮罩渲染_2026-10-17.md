# 承影覆盖纹理与原有影子节点

此实现基于回退后的影子系统。`ShadowedGeometry` 仍在 `_ready()` 中按承影槽位生成 `shadow_box` 和 `shadow_visual`，节点直接留在投影物体下，数组、激活规则和原有投影变换均保留。一个承影槽位时有 3 个 Shadow Polygon2D，两个时有 5 个，均包含母本。新增节点名为 `ShadowBox_槽位`、`ShadowVisual_槽位`，便于检查。

## 渲染链路

1. `Game/ShadowMaskSystem` 在 Game 完成图层和相机初始化后启用。场景存在原有投影节点时才分配离屏资源；没有投影物体时不分配或停用更新。
2. 每个当前承影图层使用一个 SubViewport，共享主场景的 World2D。通过渲染可见性位，只绘制该层实体的 VisualRoot，直接复用真实贴图 Alpha、视差和物体动画。不复制物体、不复制碰撞体，也不重新运行游戏脚本。
3. 覆盖视口是打包视口的子节点，打包视口又属于主视口，明确建立同帧依赖：`ReceiverLayer → ReceiverMaskRGBA → 主画面`。仅绑定纹理而不建立这条依赖，可能读到上一帧。
4. GPU 打包 Shader 将物理 layer_id 0、1、2、3 的视觉覆盖分别写入全局 `render_receiver_mask` 的 R、G、B、A。非承影层通道清零；只为当前承影层执行绘制，曾使用的其他视口停用并复用。打包关闭混合，因此 A 通道为零不会丢掉其他通道的数据。
5. 现有 shadow_visual 增加 `Shadow_Receiver_Clip.gdshader`。每帧从原有 target_layer 取得实际 layer_id，按 SCREEN_UV 读取对应覆盖通道。输出 RGB 为零，Alpha 为原影子透明度乘以覆盖值。

纹理记录的是视觉覆盖，不是投影区域。投影区域仍由现有 ShadowVisual 多边形决定。没有物体、贴图镂空处不显示影子；物体内部显示黑影，抗锯齿和景深模糊边缘保留覆盖过渡。

## 筛选与换层

保留主画面的原可见性位，额外预留位 9～12（掩码 `0xF00`）用于物理图层筛选。这是渲染可见性位，与物理碰撞层不同。

- Game、Level 等共同祖先允许四个筛选位通过。
- DepthLayer、LayerObject、VisualRoot 及其实际视觉子节点带上本物理层的筛选位。
- 影子母本、生成的两份影子、雾、UI、选择描边不进入覆盖视口，避免把影子自身或雾当成承影物体，也避免纹理读写反馈。
- 物体原有 `update_layer_slot()` 同步筛选位；VisualRoot 内运行时加入的新视觉节点也会自动标记。
- 整层轮换继续按原承影槽位寻找目标，材质读取实际 layer_id 对应的通道。物体和 Shadow 节点不迁移到遮罩视口。
- 打包时除去图层统一的 cycle_opacity，避免与原影子的换层透明度重复相乘。

`Shadow_Controller_System.gd` 保持原样：静止两秒后仍读取 shadow_box 的世界轮廓执行 Geometry2D 布尔切割。新碎片走原初始化生成影子，覆盖视口下一帧自动反映碎片的实际画面。`can_be_shadowed` 仅控制实体切割，覆盖图包含全部目标层实体。

## 黑夜雾

原来的彩色雾在影子之后合成，会把纯黑影子染灰。因此 Level 新增 `is_night`，Level09～12 开启；夜间雾的 RGB 改为黑色，Alpha、流动和景深规则保持。日间雾保持原色。

本次的投影位置沿用回退版本的计算，没有混入头部光源或表面照明重构；黑色背景图仍待后续补充。

后续关卡层的原生 PointLight2D 照明作为独立模块接入，使用方式见 [关卡层照明说明](./关卡层照明_2026-10-17.md)。跨层投影计算仍由本文件描述的原系统负责。

## 调试

运行正式游戏后，在远程场景树选中 `Game/ShadowMaskSystem`：

| debug_view | 显示 |
| --- | --- |
| 正常裁切（0，默认） | 按承影覆盖裁切后的影子 |
| 完整影子（1） | 原有完整影子，用于核对投影位置 |
| 覆盖纹理（2） | 将 debug_layer_id 对应通道显示为黑白图 |

初始 Level09 的 20 个投影物体各有母本和一对生成节点，共 60 个 Shadow Polygon2D；第三层的 5 对影子激活。第四层承影覆盖存入 A 通道。

## 验证

在项目目录运行真实渲染测试，窗口会自动退出：

```powershell

```

不能使用 `--headless`。输出保存在忽略的 `.godot/shadow_mask_qa/`，图像回读只存在于测试脚本。

测试先检查未调整布局的 Level09：节点数量、父子归属、实际箱子的纯黑投影、完整影子与裁切结果的空白对照、覆盖图排除雾与影子自身。后续在内存中验证透明贴图、动态视觉节点、镜头移动和缩放、窗口拉伸、双向整层轮换、物体换层、逐帧移动、两秒实体切割及碎片、两个承影层同时输出，以及回到日间和菜单后的清理。不会修改保存的关卡布置。

2026-10-17 在 Godot 4.7.2、D3D12 Mobile、RX 7650 GRE 上完成 180 项检查，全部通过。遮罩同步 CPU P95 为 0.026 ms，Level09 绘制调用数为 48；同步耗时不包含 GPU 绘制成本，不能据此保证其他设备的帧率。

## 边界

当前 RGBA 覆盖支持最多四个物理图层。需要更多图层时应扩展为图集。

适用于不透明实体和透明镂空贴图；大面积连续半透明实体若需要严格保持后方背景的合成结果，应改在图层合成阶段处理阴影。当前独立黑影叠加方式会影响这类材质后方的背景。
