## 一、关卡参数改为可配置

### 1. 参数从全局常量迁移到关卡

新增 `Level/Level.gd`，并挂载到关卡根节点。以下参数现在可以直接在关卡检查器中编辑：

- `layer_count`：图层数量；
- `layer_scale`：相邻图层的缩放和视差倍率；
- `current_layer_index`：玩家所在关卡层的位置。

关卡初始化时会调用 `write_to_global()`，将参数写入 `Global`，并按下面的关系生成全部槽位倍率：

```text
layer_scales[index] = layer_scale ^ (index - current_layer_index)
```

这样一来，前景、关卡层和后景不再依赖一组写死的倍率数组。不同关卡可以在同一套系统下尝试不同层数、层间差异和玩家景深位置。

当前原型关卡没有单独覆盖这些导出值，因此实际使用的是脚本默认配置：

```text
layer_count = 4
layer_scale = 0.8
current_layer_index = 1
```

### 2. 系统自动发现关卡图层

`SystemController` 不再由主场景手动保存四条 Layer NodePath，而是只引用关卡根节点，并在初始化时遍历其直接子节点，自动收集全部 `DepthLayer`。

初始化阶段会检查：

- Player、Camera、Level 引用是否存在；
- `current_layer_index` 是否超出图层范围；
- 各图层槽位是否重复；
- 实际收集到的图层数量是否与关卡配置一致。

这一调整减少了新关卡的总装工作。只要关卡根节点配置正确，系统就能自行建立图层列表，不再需要逐个连接引用。

### 3. 当前仍存在的配置边界

图层参数已经完成数据化，但系统中仍有部分四层假设：

- `DepthLayer` 的槽位枚举仍固定为 `FRONT / CURRENT / MIDDLE / BACK`；
- `DepthLayer.set_slot()` 仍使用小于 `4` 的固定边界；
- 原型关卡本身仍固定放置四个图层；
- 部分绘制顺序仍以四层布局为基准计算。

因此，当前状态更准确地说是“关卡参数已经可编辑”，但任意层数的完整适配尚未结束。后续需要清除这些硬编码，并补充非四层配置的验证场景。

## 二、无人机操作优化

### 1. 增加召唤条件

无人机现在只能在人物处于地面时召唤。`PlayerController.UAV_activate()` 会返回本次切换是否成功；如果人物在空中尝试召唤，系统不会改变无人机状态，也不会生成用于保留人物身体的临时实体。

关闭无人机不受该限制，以免玩家因当前位置或碰撞状态无法恢复人物控制。

### 2. 增加活动距离限制

无人机与人物身体之间增加了最大距离，当前默认值为 `400`。无人机超过限制时，会根据超出的距离获得指向人物的修正速度，使其逐渐返回允许范围。

这一限制解决了无人机可以无限离开人物的问题，也为后续城市关卡的视角操作建立了明确范围。

### 3. 调整移动手感

无人机现在拥有独立的运动参数：

```text
UAV_move_speed = 350
UAV_friction_deceleration = 20
UAV_distance = 400
```

无人机的水平和垂直输入先累积到速度，再应用独立摩擦，最后按最大速度限制整个速度向量。没有足够剩余速度时会直接归零，减少低速漂移。

### 4. 整理状态归属

无人机状态从 `Global` 中移出，由 `SystemController` 和 `PlayerController` 分别管理系统状态与角色表现。用于保留人物身体的 `Player_Object` 引用也移动到 Player 中，使距离约束和人物恢复可以直接读取该实体。

退出无人机时，系统会先让人物身体所在内容层回到当前关卡槽位，再恢复人物位置和缩放，最后释放临时实体。

## 三、物件继承关系简化

此前 Box、Goal、Ground 和 Player Object 分别重复实现视觉换算、碰撞组切换和尺寸更新。今天将这些共同行为集中到 `LayerObject`：

- 统一取得 `CollisionBox` 和 `VisualRoot`；
- 统一根据锚点与槽位更新视觉位置和比例；
- 统一切换 collision layer 与 collision mask；
- 统一处理物件跨层时的位置和碰撞尺寸换算；
- 子类只保留自身特有的选中反馈或交互逻辑。

同时删除了原有 `object_id` 和 `size_step`。物件换层后不再重新计算离散尺寸等级，而是直接按照新旧槽位倍率之比累乘 `CollisionBox.scale`。

相关场景也统一将实体碰撞节点命名为 `CollisionBox`，并保证根节点下存在：

```text
LayerObject
├─ CollisionBox
└─ VisualRoot
```

这次重构减少了重复代码，也明确了物件组件的最低结构要求。Box、Goal、Ground 和 Player Object 的脚本现在主要负责各自的特殊交互。

除此之外，鼠标选择逻辑增加了 `input_pickable` 检查，并在切换选择对象时显式关闭旧对象的选中状态，避免不可点选区域被误判。

## 四、影子系统初步接入

### 1. 新增可投影物件

新增组件：

```text
Component/Object/Shadowed_Geometry/
├─ Shadowed_Geometry.tscn
└─ Shadowed_Geometry.gd
```

`ShadowedGeometry` 继承 `LayerObject`，当前以 `RigidBody2D` 为物理根节点，包含：

- 实体 `CollisionBox`；
- 普通物件使用的 `VisualRoot`；
- 选中轮廓与鼠标点选区域；
- 作为影子复制模板的黑色多边形 `Shadow`。

原型关卡已经在 `Layer2` 中加入一个 `ShadowedGeometry` 实例，用于验证第三层物件向更后方图层投影的效果。

### 2. 影子的几何与视觉分离

当前代码使用两组影子实例：

- `shadow_box`：保存影子在目标层中的几何基准；
- `shadow_visual`：根据目标层景深倍率换算后的最终画面表现。

每帧更新时，系统先根据光源锚点、投影物件与目标层之间的相对层距计算影子基准的位置和比例，再将该结果转换为目标槽位中的屏幕位置和画面比例。

这一步已经解决了影子随视角移动时的位置和大小换算问题，也使影子的空间计算与最终视效保持分离。

### 3. 绘制顺序调整

物件自身的 `VisualRoot.z_index` 改为在初始化和主动换层时更新，不再每帧重复设置。影子则被放置在投影物件与承影层之间的绘制层级，使黑色影子能够覆盖后方物体，同时不遮挡前方投影物。

## 五、影子管理的当前问题

目前影子实体在 `_ready()` 中依据物件的初始槽位创建：只有当物件初始位于关卡层之后，才会为它后方的槽位生成影子。

这种方式在初始状态下能够显示正确结果，但无法适应运行时的图层变化：

- 物件或整体图层轮换后，物件当前槽位可能与初始化时不同；
- 已创建的影子数量可能少于新状态所需数量；
- 当前不需要的影子没有统一关闭，可能残留在画面中；
- 影子的创建条件和启用条件绑定在一起，难以维护；
- 影子数组依赖创建顺序，缺少“目标槽位 → 影子实体”的明确映射。

因此，目前完成的是影子实体的基础变换和显示验证，尚未完成可靠的生成与管理流程。

## 六、计划采用的影子管理逻辑

下一步应将“创建影子”和“启用影子”彻底分开。

### 1. 初始化阶段：固定建立影子池

不论物件初始化时位于哪个槽位，都为下面这些目标槽位预先建立影子实体：

```text
current_layer_index + 2 ... layer_count - 1
```

每个目标槽位保存一组几何基准和视觉实例，并以目标槽位作为索引。影子池只依赖关卡配置，不依赖物件的初始位置。

### 2. 每帧阶段：判断是否启用

每帧更新时读取物件当前的 `owner_layer.slot`，再逐个判断影子池中的目标槽位是否满足投影条件。

按现有光源关系，启用条件应至少包括：

```text
物件位于当前关卡层之后
目标槽位位于物件之后
目标槽位属于允许承接影子的范围
```

满足条件时：

1. 启用对应影子；
2. 更新影子的几何位置和比例；
3. 更新影子的画面位置、比例和绘制顺序。

不满足条件时，应立即关闭对应影子的显示和碰撞，不保留上一帧状态。

### 3. 配置变化时重建

正常的图层轮换和物件换层只切换影子池中各实例的启用状态，不应重复创建或删除节点。只有关卡的 `layer_count` 或 `current_layer_index` 发生结构性变化时，才需要重建影子池。

这样可以保证：

- 影子数量始终覆盖所有可能的目标层；
- 图层轮换不会产生缺失或残留；
- 创建逻辑与显示逻辑职责清晰；
- 后续加入影子碰撞、布尔运算或静止计时逻辑时，有稳定的实体可以复用。
