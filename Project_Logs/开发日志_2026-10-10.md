# PICTOUR 开发日志｜2026-10-10

## 今日概览

今天主要补全了图层操作的碰撞安全机制。物体改变图层和玩家轮换图层前，系统会先在静态物理世界中检测目标状态；如果目标位置已经被占用，本次操作会被取消，从而避免物体互相嵌入或玩家进入障碍物内部。

同时，项目中的实体碰撞箱统一为 `CollisionPolygon2D`，并整理了换层变换的计算与应用流程，使碰撞检测使用的候选状态和最终实际状态保持一致。

> 今日尚未产生新的 Git commit。本日志以当前工作区中的实际代码和场景差异为准。

## 一、图层操作碰撞检测

### 1. 物体改变图层

物体换层前，`LayerControllerSystem` 会根据源层和目标层的缩放倍率计算：

- 物体在目标层中的位置；
- 物体实际尺寸的缩放比例；
- 碰撞多边形最终使用的变换。

随后使用目标图层对应的物理层作为查询遮罩，检测候选碰撞多边形是否与目标层中的物体重叠。存在有效冲突时直接取消换层；检测通过后才修改物体所属图层。

缩放比例仍遵循：

```text
ratio = source_layer_scale / target_layer_scale
```

物体位置围绕相机锚点同步换算，因此检测结果与实际换层后的位置一致。

### 2. 玩家轮换图层

玩家进行整体图层轮换前，系统会找到轮换后即将成为关卡层的物理图层，并使用玩家当前生效的碰撞多边形进行检测：

- 普通状态使用玩家本体碰撞箱；
- 无人机状态使用无人机碰撞箱。

只有检测通过后，系统才会继续修改玩家的碰撞层以及各 `DepthLayer` 的槽位，避免出现图层已经轮换、玩家碰撞层却没有同步的中间状态。

### 3. 无人机收回例外

`layer_cycle` 信号增加了 `check_collision` 参数：

- 玩家主动轮换图层时传入 `true`；
- 无人机收回并复位图层时传入 `false`。

因此，无人机收回流程不会被目标层碰撞检测中断，也不会因轮换失败而停留在复位循环中。

## 二、接触容差处理

最初的相交查询会把物体与地面的正常接触也视为冲突。由于各图层地面保持平行，站立物体在目标层中通常只会与地面接触，而不应因此禁止换层。

当前检测改为使用 `collide_shape()` 返回的成对接触点计算穿透深度：

```text
penetration_depth <= 0.5 px  视为正常接触
penetration_depth > 0.5 px   视为有效冲突
```

该处理不会修改真实碰撞箱，只在换层可行性查询中忽略极浅重叠。容差统一保存在 `COLLISION_TOLERANCE` 中，后续可以根据关卡尺度继续调整。

## 三、碰撞箱统一为 CollisionPolygon2D

为减少兼容分支，项目中的实体碰撞箱统一改为 `CollisionPolygon2D`：

- `Box` 的实体碰撞和鼠标点选区域改为多边形；
- 玩家本体和无人机碰撞箱改为多边形；
- `LayerObject.collision_box` 明确声明为 `CollisionPolygon2D`；
- 玩家控制器中的两个碰撞箱引用同步收窄类型；
- 图层控制器删除 `CollisionShape2D` 的查询分支；
- 影子控制器删除重复的类型判断和强制转换。

碰撞查询会先通过 `Geometry2D.decompose_polygon_in_convex()` 将候选多边形拆成凸多边形，再逐块交给物理空间检测，因此同一套流程可以处理矩形和后续布尔切割产生的不规则轮廓。

部分场景中的点选碰撞节点仍保留旧名称 `CollisionShape2D`，但节点实际类型已经是 `CollisionPolygon2D`。为避免无意义地扩大场景改动，本次没有仅为命名进行重构。

## 四、换层变换流程整理

此前，目标位置和缩放比例分别在 `LayerControllerSystem` 与 `LayerObject` 中计算，存在重复逻辑，也可能使碰撞检测结果与最终应用状态产生偏差。

现在流程调整为：

1. `LayerControllerSystem` 统一计算目标物体变换和目标碰撞箱变换；
2. 使用同一组变换执行碰撞检测；
3. 检测通过后，将两组变换直接传给 `LayerObject.transfer_to()`；
4. `LayerObject` 只负责重新挂接父节点、应用变换和更新所属图层。

这样，候选状态只计算一次，并同时作为“检测结果”和“最终执行结果”的依据。

无界面启动不会自动执行完整的玩家输入流程，因此仍需在编辑器中人工验证：

1. 站在平行地面上的物体可以正常换层；
2. 目标层存在墙体或其他物体时换层被阻止；
3. 玩家目标位置被占用时图层轮换被阻止；
4. 无人机收回可以无条件完成图层复位；
5. 凹多边形物体经过凸分解后不会产生遗漏或误判。

## 七、当前边界与后续工作

1. `0.5` 像素容差适用于当前白模尺寸，正式关卡确定单位尺度后需要再次校准。
2. 复杂凹多边形每次查询都需要执行凸分解；如果后续频繁检测或碎片数量较多，可以在物体几何变化时缓存分解结果。
3. 当前查询只检测 `PhysicsBody2D`，不会把点选用的 `Area2D` 当作障碍物，符合现有职责划分。
4. 所有参与图层转换的物体现在都必须提供有效的 `CollisionPolygon2D`，且轮廓至少包含三个顶点。

今天的更新使图层转换从“直接执行”变为“先验证、再原子执行”，补齐了核心玩法在实际关卡中避免穿模和状态错位所需的基础保护。
